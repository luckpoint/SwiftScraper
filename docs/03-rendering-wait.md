# 03. レンダリング待機

## 目的
JavaScript による動的描画が終わるまで待機し、未完成の DOM を取得してしまうことを避ける。

## 要件
- `didFinish` のみで描画完了と判定しないこと
- 条件付き待機と最大待機時間を組み合わせられること
- SPA や遅延描画ページに対応できること

## 実装済み待機パラメータ
- `--wait-delay`: `didFinish` 後の固定待機
- `--auto-scroll`: lazy load 補助のため下方向へ自動スクロール
- `--wait-selector`: `document.querySelector(...)` の一致待機。複数指定可
- `--wait-text`: `document.documentElement.innerText` に対する部分一致待機。複数指定可
- `--poll-interval`: 条件再確認の間隔。既定 0.5 秒
- `--dom-stable-delay`: DOM が変化しない状態を何秒維持したら完了とみなすか。既定 0.5 秒、`0` で無効
- `--wait-timeout`: 描画待機全体の上限。既定 15 秒

## 主な待機戦略
- 一定時間待機
- 下方向への自動スクロール
- 特定 CSS セレクタの出現確認
- 特定テキストの出現確認
- 複数回ポーリング
- `document.documentElement.outerHTML` の変化監視による DOM 安定待機
- 最大待機時間でのタイムアウト

## 処理概要
1. ナビゲーション完了イベントを受け取る
2. `--wait-delay` があれば先に固定待機する
3. `--auto-scroll` が有効なら待機予算内で下方向へスクロールして lazy load を促す
4. セレクタ / テキスト条件を評価する
5. 条件未達なら `--poll-interval` 間隔で再確認する
6. `--dom-stable-delay` が有効なら DOM スナップショットが変化しない状態を監視する
7. 条件充足またはタイムアウトで次工程へ進む

## 完了条件
- 必要な描画条件を満たしたと判断できること
- もしくはタイムアウトにより待機を打ち切ること

## 注意点
- `didFinish` 後も DOM が更新され続けるページがある
- 固定待機、自動スクロール、条件待機、DOM 安定待機は同じ `--wait-timeout` の予算を共有する
- DOM が継続的に変化するページでは `--dom-stable-delay 0` にして明示条件だけで待つ方が安定する場合がある
- `--auto-scroll` は文書全体のスクロールにだけ効く。内部スクロールコンテナを持つ UI には別対応が必要な場合がある
